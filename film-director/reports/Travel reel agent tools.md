# Build the director, reuse the plumbing

The best open-source foundation for a travel "film director" agent is a Python 3.12 pipeline built from a small set of permissively licensed tools. **FFmpeg** renders, using its 58 built-in `xfade` transitions plus `zoompan` for Ken Burns on photos. **PySceneDetect, OpenCV, imagededup, open_clip and the LAION aesthetic predictor** pick the shots. **beat_this plus librosa** find beats, downbeats and energy. **ExifTool plus an offline reverse geocoder** set the order of the story. The **Epidemic Sound MCP connector** supplies music and edits it to an exact length of 60 s or less. No existing project does this whole job well. The most-starred "AI short video" repos, such as MoneyPrinterTurbo at about 134K stars, generate narrated videos. They are built around TTS and subtitles, which this brief excludes, and none of them cuts the user's own footage to a beat grid. The projects that do beat-sync user photos and clips are small 2026 repos, mostly packaged as Claude Code or Codex skills. They are worth studying, but none is solid enough to build on. The recommendation is therefore to reuse the commodity layers (render, analysis, metadata, music) and build the director layer yourself: scoring, a beat- and energy-aware edit plan, a JSON edit decision list (EDL), an approval step, and license bookkeeping. Ratings in this report combine GitHub stars, maintenance in 2026, license fit and how hard each tool is to install headless. Star counts are approximate snapshots from late October 2026.

## FFmpeg's 58 xfade transitions beat every heavier rendering engine

### Rendering speed and licensing decide the engine

FFmpeg is the clear primary engine. It is the most-starred scriptable editor (**~65.8K stars, release 9.0.2 on 2026-09-18**) and it is LGPL at its core ([GitHub API](https://api.github.com/repos/FFmpeg/FFmpeg); [ffmpeg.org](https://ffmpeg.org/download.html)). In one benchmark, a 30 s 1080p template with three scenes rendered in **7.5 s with a single FFmpeg filtergraph**. The same job took **10.2 s with MLT, 18.2 s with Remotion, 21.8 s with Revideo and 86.6 s with MoviePy**, and Editly failed to build at all on a current Node ([videobycode](https://videobycode.com/articles/generating-video-from-json-schema-payload-and-render/)). That was a single run on Apple arm64, so the ratios are directional. Even so, an 11x gap matters for an agent that re-renders after each round of feedback.

Remotion has the most stars of any engine (~67.4K), but it is **not OSI open source**. The free license covers individuals and companies of up to 3 employees. Automated rendering under the "Remotion for Automators" plan costs **$0.01 per render with a $100/month minimum** ([Remotion license](https://www.remotion.dev/license); [remotion.pro](https://www.remotion.pro/license)). HyperFrames from HeyGen is the permissive alternative for agent-authored HTML video (**Apache-2.0, ~73K stars**). Its default output is 1920×1080, so vertical output must be requested explicitly ([hyperframes.dev](https://www.hyperframes.dev/); [prompting docs](https://hyperframes.heygen.com/prompting/overview)). Both are good choices for an optional animated title card or map overlay. Neither should be the core cutter.

Generating plain filter strings and running them through `subprocess` is an equally valid choice with no dependency at all.

### Stock xfade already covers every reel transition

Out of the box, FFmpeg's `xfade` filter provides **`fade`/`dissolve` (crossfade), `fadewhite` (flash), `slideleft`/`slideright` and `cover`/`reveal` variants (slide), `zoomin` (zoom), and `hblur`, `squeezeh` and pixelize effects**, plus a `custom` expression mode. `zoompan` produces Ken Burns motion on stills ([FFmpeg filters docs](https://ffmpeg.org/ffmpeg-filters.html); [Xfade gallery](https://trac.ffmpeg.org/wiki/Xfade)). No tool ships a true "whip pan". It has to be composed, for example from a 0.2–0.3 s slide combined with blur. For a wider creative range, **xfade-easing** transpiles most of the **100+ MIT-licensed gl-transitions** into expressions that stock FFmpeg can run, and adds CSS-style easing. The cost is roughly **½ minute per transition at SD and 1½ minutes at HD** in expression mode ([xfade-easing](https://github.com/scriptituk/xfade-easing); [gl-transitions](https://github.com/gl-transitions/gl-transitions)). A 60 s reel should therefore use these sparingly, only on two or three accent cuts. MoviePy has the thinnest built-in vocabulary (CrossFade and SlideIn) ([MoviePy fx](https://zulko.github.io/moviepy/reference/reference/moviepy.video.fx.html)).

Two sources in the research seem to conflict. FFmpeg's documentation recommends chaining `xfade`, while a travel-vlog agent skill warns that **"xfade chain merges drop frames — use concat instead"** ([vlog-auto-edit](https://github.com/znyupup/ai-video-editing-skill)). The two are compatible once you read the constraint: `xfade` requires both inputs to have the same resolution, pixel format, constant frame rate and timebase. Each chained offset must also subtract the earlier transition durations ([FFmpeg docs](https://ffmpeg.org/ffmpeg-filters.html); [Xfade wiki](https://trac.ffmpeg.org/wiki/Xfade)). The practical design for a beat-cut reel follows from this. Normalize every segment to 1080×1920, 30 fps CFR, `yuv420p`. Make most cuts hard cuts joined with concat, because hard cuts are what land on the beat. Reserve `xfade` for a handful of planned accents, and assert the output frame count after every render.

## Shot selection runs on CPU with five permissive libraries

### Classical CV filters first, CLIP embeddings second

Choosing highlights does not need research-grade video-highlight models. At trip scale (hundreds of photos and tens of phone clips), the whole selection stack runs on CPU. **PySceneDetect** (~5.3K stars, BSD-3, **v0.7.2 on 2026-10-12**) splits clips into shots. Its `AdaptiveDetector` is designed to "handle fast camera movement better", which suits handheld footage ([PySceneDetect](https://github.com/Breakthrough/PySceneDetect); [PyPI](https://pypi.org/project/scenedetect/)). **OpenCV** (~91.4K stars, Apache-2.0, 5.0 released June 2026) provides variance-of-Laplacian blur scoring and exposure gates ([GitHub](https://github.com/opencv/opencv); [PyPI](https://pypi.org/project/opencv-python/)). **imagededup** (~5.7K stars, Apache-2.0) removes burst duplicates with PHash and DHash, and notes that "difference hashing is the fastest" ([imagededup](https://github.com/idealo/imagededup)).

**open_clip** (~14.2K stars, MIT, **3.3.0 in Feb 2026**) is the maintained way to run CLIP. The original OpenAI CLIP repo has 34.5K stars but has effectively been frozen since 2024. One ViT-L/14 forward pass per candidate frame produces an embedding that serves three purposes. It is the input to the **LAION improved-aesthetic-predictor** (Apache-2.0, an MLP on CLIP embeddings). It drives zero-shot tags such as "beach", "food" or "city street", which group the storyboard. And its cosine similarity removes semantic near-duplicates ([open_clip](https://github.com/mlfoundations/open_clip); [aesthetic predictor](https://github.com/christophschuhmann/improved-aesthetic-predictor)). The SigLIP 2 models, available through transformers 5.21.0, are a stronger alternative for zero-shot tagging. They outperform SigLIP at every model size ([arXiv 2502.14786](https://arxiv.org/html/2502.14786v1)).

The licenses are the trap in this category. **pyiqa**, the most complete image-quality toolbox, moved to **PolyForm Noncommercial 1.0.0** in its 2026 releases ([PyPI](https://pypi.org/project/pyiqa/)). The SigLIP-based aesthetic predictor v2.5 is **AGPL-3.0**. If the agent might ever serve paying users, both are out, and the Apache-licensed LAION predictor is the safe choice. Query-conditioned highlight models such as Moment-DETR and UniVTG are built to find moments inside long YouTube videos. They ship as 2021–2023 research code and expect a GPU. Moment-DETR's annotations are also CC BY-NC-SA ([Moment-DETR](https://github.com/jayleicn/moment_detr); [UniVTG](https://github.com/showlab/UniVTG)). For phone clips of 3–30 s, picking the best moment of each shot matters more, and CLIP-prompt similarity combined with quality scores gives a comparable signal without that machinery. One caveat: no published study validates LAION aesthetic scores against human picks on personal travel photos. Calibrate the thresholds (blur, cosine dedup at about 0.9) on the user's own footage.

### ExifTool turns capture time and GPS into a storyline

Without narration, a travel reel's narrative comes from chronology and place. **ExifTool**, called through **PyExifTool** (0.5.6, GPL/BSD) or `exiftool -json -n -G`, is the single most complete reader. It handles HEIC and JPEG `DateTimeOriginal` with `OffsetTimeOriginal`, and iPhone QuickTime `CreationDate` and GPS, in one call ([PyPI PyExifTool](https://pypi.org/pypi/PyExifTool/json)). iPhone MOV files keep GPS in `com.apple.quicktime.location.ISO6709` and the offset-aware time in `com.apple.quicktime.creationdate` ([addpipe](https://blog.addpipe.com/geolocation-metadata-ios-android-video-files/)). One critical rule: **FFmpeg does not copy iOS location metadata when remuxing MOV to MP4** (trac #4209), so metadata must be read from the originals before any transcode ([FFmpeg trac](https://ffmpeg.org/pipermail/ffmpeg-trac/2024-April/069027.html)). ffprobe works as a fallback for video. Pillow 13 with pillow-heif 1.8.1, or exifread 3.5.1, gives a pure-Python path for photos. **timezonefinder 9.2.0** converts UTC-only video timestamps to local time from GPS ([PyPI pillow-heif](https://pypi.org/pypi/pillow-heif/json); [PyPI timezonefinder](https://pypi.org/pypi/timezonefinder/json)).

For offline place labels, **reverse-geocode** (1.6.6, May 2025, pure-Python wheel, LGPL) is the lower-risk install. **reverse_geocoder** has more stars (~1.9K), but its last release was in 2016, it ships as sdist only, and it has open multiprocessing bugs ([PyPI reverse-geocode](https://pypi.org/pypi/reverse-geocode/json); [reverse_geocoder issues](https://api.github.com/search/issues?q=repo:thampiman/reverse-geocoder+is:issue)). Both return the nearest populated place, which is too coarse for landmarks. For occasional landmark lookups, use **geopy** (MIT, 2.5.0) with the public Nominatim server. That server allows **at most 1 request/s** and requires an identifying User-Agent ([PyPI geopy](https://pypi.org/pypi/geopy/json); [OSM diary](https://api.openstreetmap.org/user/pnorman/diary/398773)).

## beat_this and librosa split the beat job cleanly

**beat_this** (CPJKU, ISMIR 2024) is the best beat tracker for this pipeline. Both its code and its model weights are **MIT**. It installs with pip (1.1.0, April 2026), it outputs **beats and downbeats**, and its 8.1 MB "small" model runs fine on CPU ([beat_this](https://github.com/CPJKU/beat_this); [PyPI](https://pypi.org/pypi/beat-this/json)). On held-out GTZAN it scores **about 89.1 beat F1 and 78.3 downbeat F1**. Those figures come from secondary summaries of the paper ([Moonlight review](https://www.themoonlight.io/review/beat-this-accurate-beat-tracking-without-dbn-postprocessing)). **librosa** (~8.7K stars, ISC) fills in what a beat tracker does not provide: onset strength, RMS energy and novelty curves. Those curves drive energy-aware cut density and approximate "drop" detection. Note that **librosa 1.0.0 requires Python ≥3.12**, while Python 3.11 resolves to 0.11.0 ([PyPI librosa](https://pypi.org/pypi/librosa/json)).

**allin1** is the only tool that labels song sections, which is exactly what "open on the chorus" needs. It has not been pushed since May 2024, though, and NATTEN 0.17.5 broke it through API renames ([allin1 issues](https://api.github.com/search/issues?q=repo:mir-aidj/all-in-one+natten)). An open PR from September 2026 would make NATTEN optional, but until it merges, run allin1 only inside a pinned Docker image, if at all. The music connector below largely removes the need for it, because it lets the agent anchor a chosen region at a chosen offset. Its author also reports **20–40 ms timing offsets on MP3 input** ([allin1](https://github.com/mir-aidj/all-in-one)). At 30 fps one frame lasts 33 ms, so the agent should download WAV, run beat detection on the final edited track, and snap every cut to a frame boundary.

## Epidemic Sound's MCP connector solves the music step

### One connector handles search, exact length and stems

Music is the one category where a commercial connector beats every open-source option. The **Epidemic Sound MCP connector** joined Claude's directory on **1 September 2026**. It searches **55,000+ tracks** by brief, mood, BPM, genre, key, instrument or Spotify reference, and downloads full tracks or stems ([press release](https://corporate.epidemicsound.com/press-and-media/press-releases/2026/epidemic-sound-launches-mcp-connector-in-claudes-directory); [Epidemic blog](https://www.epidemicsound.com/blog/mcp-server)). Its most important tool for a reel is **`EditRecording`**. It reshapes a track to an exact `targetDurationMs` and accepts `requiredRegionsAtOffsets`. The docs' example is "a 47-second version with the chorus at 0:15", which lets the agent pin the drop onto the reveal shot ([developer docs](https://developers.epidemicsound.com/docs/mcp); [tools page](https://www.epidemicsound.com/tools/mcp)). In a live test during this research, a search for "upbeat summer travel adventure" at 110–130 BPM with no vocals returned **500 matches**. Each result came with BPM, mood tags, four stems (drums, bass, melody, instruments) and a waveform JSON. **None returned beat timestamps**, so local beat detection is still required, ideally on the DRUMS stem of the edited file. Two gaps remain open: `PollEditRecordingJob` "may not be available" on OAuth connections such as Claude's directory connector ([docs](https://developers.epidemicsound.com/docs/mcp)), and nobody has yet read the full MCP software license agreement.

Licensing follows the user's own subscription. The **Creator Plan covers Instagram, TikTok and YouTube only for non-commercial users**, and content published while subscribed stays covered after the user cancels ([Epidemic Help](https://help.epidemicsound.com/hc/en-us/articles/26247405706386-Creator-Plan)). The agent should therefore record the track ID and the plan type, and flag sponsored or branded reels as needing a business plan.

### The best beat-sync projects are tiny agent skills

Among existing agent projects, popularity and fit point in opposite directions. **MoneyPrinterTurbo** (~134K stars, MIT, very active) accepts the user's own images and videos and exports 1080×1920. Its pipeline, though, is LLM script → TTS → subtitles, and music is a background layer with no beat sync ([README](https://github.com/harry0703/MoneyPrinterTurbo); [GStars](https://www.gstars.dev/repo/harry0703/MoneyPrinterTurbo)). NarratoAI, ShortGPT (stale since February 2025) and FunClip are likewise built around narration or ASR, which conflicts with the no-transcription requirement. **Director** (video-db) depends on the hosted VideoDB service. **VideoAgent** (HKUDS) claims beat-synced edits but needs Claude, GPT and Gemini keys all at once ([Director](https://github.com/video-db/Director); [VideoAgent](https://github.com/HKUDS/VideoAgent)).

The projects that actually beat-sync user photos and clips are small repos from 2026. **beat-synced-edit** (MIT, ~30 commits) ships a Claude Code skill with a pipeline that maps almost one-to-one onto this agent. `beat_map.py` uses librosa to find beats, energy peaks and valleys. `clip_tag.py` uses PySceneDetect for shots plus motion and brightness scores. `plan_edit.py` matches high-energy clips to energy peaks. Separate scripts handle FFmpeg rendering, `fadewhite` flashes, punch-ins and 9:16 styling ([beat-synced-edit](https://github.com/ZiadAbdelkarim/beat-synced-edit)). **beat-sync-video-editor** (a Codex skill with one commit and no license shown) contributes the craft rules: "Do not distribute cuts uniformly from BPM alone", place an action climax "roughly 0.20–0.30 seconds before the interval ends", and get the beat map approved by a human before rendering ([beat-sync-video-editor](https://github.com/330312/beat-sync-video-editor)). **Montage AI** (~60 stars, no license asserted) adds JSON style templates and OTIO/EDL export. **BeatSync Engine** (**AGPL**) adds "energy-wave cut density", where calm sections hold longer and drops cut faster. **Immich Memories** (MIT) adds face-aware Ken Burns on photos and a review-every-shot loop ([Montage AI](https://github.com/mfahsold/montage-ai); [BeatSync Engine](https://github.com/Merserk/BeatSync-Engine); [Immich Memories](https://github.com/sam-dumont/immich-video-memory-generator)).

The MCP-server landscape for editing is thin. **DaVinci Resolve MCP** (~3.8K stars, MIT, active, 390 granular tools) is the only mature one. It requires Resolve to be installed, which makes it an optional handoff to a professional editor, not part of an automated pipeline ([davinci-resolve-mcp](https://github.com/samuelgursky/davinci-resolve-mcp)). The FFmpeg MCP servers are small or stale: video-audio-mcp has ~89 stars and no commit since May 2025, and ffmpeg-mcp-lite has 9 commits. The Video Jungle MCP requires a SaaS account ([video-audio-mcp](https://github.com/misbahsy/video-audio-mcp); [ffmpeg-mcp-lite](https://github.com/kevinwatt/ffmpeg-mcp-lite); [video-editing-mcp](https://github.com/burningion/video-editing-mcp)). Ranked for this use case, the order is: beat-synced-edit (closest template), then beat-sync-video-editor and Immich Memories (design patterns), then Montage AI, then DaVinci Resolve MCP (pro handoff), then video-audio-mcp. Narration generators come last, useful only for their 9:16 export plumbing.

## A recommended stack with a JSON edit plan at its core

The recommended stack below targets **Python 3.12**. librosa 1.0, timezonefinder 9.2 and Pillow 13 already require Python ≥3.11 or ≥3.12, and the newest essentia wheels are cp314-only. Every core component is permissively licensed, or runs as a separate binary that keeps its GPL obligations outside the app's code.

| Layer | Reuse | License |
|---|---|---|
| Render | FFmpeg 9.x via typed-ffmpeg or subprocess; `xfade` + `zoompan`; xfade-easing for 2–3 accent transitions | LGPL/GPL (separate binary), MIT |
| Shot analysis | PySceneDetect AdaptiveDetector → OpenCV blur/exposure gates → imagededup | BSD-3, Apache-2.0 |
| Scoring and tags | open_clip ViT-L/14 → LAION aesthetic MLP + zero-shot tags + cosine dedup | MIT, Apache-2.0 |
| Story order | ExifTool/PyExifTool → timezonefinder → reverse-geocode (geopy for landmarks) | GPL binary, MIT, LGPL |
| Music | Epidemic Sound MCP (`SearchRecordings` → `EditRecording` to ≤60,000 ms → `DownloadRecording` WAV + stems); Freesound MCP for whooshes | Subscription / CC per sound |
| Beats | beat_this (beats/downbeats) + librosa (energy, onsets) on the edited track's DRUMS stem | MIT, ISC |
| Optional | HyperFrames for animated title or map card; DaVinci Resolve MCP / OTIO for pro handoff | Apache-2.0, MIT |

The part to build is the director. It has five components, and no open-source project provides any of them in a mature, permissively licensed form. First, an **ingest-and-score module** that turns raw media into candidate shots of 1.5–3 s, each with quality, aesthetic, tag and timestamp/location metadata. Second, a **planner** that maps those shots onto the song's energy curve and downbeats: a hook in the first one to three seconds, the journey in chronological order, the climax on the anchored drop, and an outro that ends on a complete musical phrase. Third, a **deterministic EDL JSON schema**, which is the contract between Claude's creative plan and the renderer. vlog-auto-edit's `edit_plan.json` and Montage AI's style templates are useful precedents ([vlog-auto-edit](https://github.com/znyupup/ai-video-editing-skill); [Montage AI](https://github.com/mfahsold/montage-ai)). Fourth, a **thin custom render tool**: a few well-tested FFmpeg calls exposed as a skill or a small MCP server, which beats adopting a stale third-party FFmpeg MCP. Fifth, an **approval step and license ledger** that record the track ID, the plan type and any CC attribution text. The strongest argument against building is that beat-synced-edit is MIT-licensed and could be forked on day one. That is a reasonable way to bootstrap, but at about 30 commits the repo offers a starting sketch, not a maintained dependency. Its planner and effects are exactly the parts the director must own anyway.

## Conclusion

The research changes what "build vs reuse" means for this agent. Each individual capability is a solved, permissively licensed commodity: rendering, transitions, shot detection, aesthetics, beats and metadata. The open-source ecosystem's center of gravity, by stars, sits in narration-driven generators that solve a different problem. What is genuinely missing is editorial judgment encoded as data: which shot earns the downbeat, when to hold and when to cut fast, and how the trip's chronology bends into a three-act arc within 60 seconds. Small 2026 agent skills already treat that judgment as the product. So the useful build target is a planner and an EDL schema, not an editor. Music connectors also shift the work. Epidemic's ability to cut a track to an exact length with an anchored drop turns the hardest audio problem into a single API call, which leaves beat timing and visual pacing as the director's real job.

The open questions are empirical, not architectural. No source benchmarks aesthetic scoring against human picks on travel photos.
