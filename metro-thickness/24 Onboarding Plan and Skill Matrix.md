# 24 · First 30/60/90 Days, Questions to Ask, Skill Matrix（入職計畫與能力矩陣）

← [[23 Daily Work and Failure Modes]] · next → [[25 Core Equations]]

## 31. 30 / 60 / 90 days — with concrete deliverables

### Days 1–30 · Understand（理解）
| Learn | Deliverable |
|---|---|
| Fab vocabulary, process flow, owned platforms, safety | Personal glossary (start from [[26 Glossary]]) |
| Film stacks for owned layers | One-page stack drawing per key layer, with what's fixed vs fitted |
| Recipe structure | Annotated walkthrough of one production recipe |
| Data flow (tool → SPC → APC) | Diagram of where each number goes |
| SPC vocabulary, OCAP | List of owned charts + their reaction plans |

**Target:** explain the full **process → film → measurement → output** path for one important application, in 10 minutes, to your manager.

### Days 31–60 · Own measurement quality（掌握量測品質）
| Learn | Deliverable |
|---|---|
| Wafer maps, raw signals, fit problems | A personal "signature gallery" of real cases |
| Repeatability, calibration | Run (or re-analyze) one GR&R study |
| Tool matching | Matching summary for one recipe across the fleet |
| Process correlation | One correlation analysis with a process engineer |
| Simple excursions | Lead triage on ≥ 1 real event, with written summary |

**Target:** take an anomaly from raw symptom to a defensible engineering hypothesis.

### Days 61–90 · Own applications（擁有應用）
| Learn | Deliverable |
|---|---|
| Recipe modification, model refinement | One recipe improvement (under change control) with before/after |
| Tool qualification | Participate in a post-PM qual |
| SPC setup, NPI support | Set up or revise one chart + OCAP |
| RCA, presentations | Present one technical review |

**Target:** independently support at least one application from monitoring through troubleshooting and improvement.

## 32. Questions to ask your manager — with why each matters

| # | Question | Why |
|---|---|---|
| 1 | Which metrology platforms do I support? | Scopes what to study first |
| 2 | Key optical/X-ray technologies? | Physics focus |
| 3 | Fleet size? | Matching workload |
| 4 | Tools dedicated or shared across layers? | Cross-layer impact of changes |
| 5 | Which film families are mine? | Ownership |
| 6 | Critical thickness ranges? | Determines technique limits |
| 7 | Single or multilayer? | Model complexity |
| 8 | n/k libraries supplied or developed locally? | Who owns model accuracy |
| 9 | Closely connected upstream modules? | Who you'll talk to daily |
| 10 | Which process parameters correlate most with thickness? | Fast RCA |
| 11 | Fixed vs fitted parameters in key recipes? | Model risk |
| 12 | Critical model assumptions? | Known weak spots |
| 13 | Reference/correlation method? | Accuracy anchor |
| 14 | Recipe acceptance criteria? | Release standard |
| 15 | Primary SPC charts? | Daily monitoring |
| 16 | Capability metric used? | Cpk vs Ppk, definitions |
| 17 | Formal excursion reaction plan? | Avoid improvising |
| 18 | How are tools matched? | Method & frequency |
| 19 | Reference wafers used? | Their history and care |
| 20 | Acceptable bias? | Matching spec |
| 21 | What data can I access remotely? | Remote support readiness |
| 22 | Primary partner teams at the other site? | Communication map |
| 23 | Escalation path for urgent excursions? | Response time |
| + | How is the uniformity metric defined here? Edge exclusion? | Avoid definitional confusion |
| + | Who owns recipe change control and how are changes reviewed? | Prevent untracked changes |
