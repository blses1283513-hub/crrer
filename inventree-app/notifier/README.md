# 通知服務（inventree-notifier）

在 InvenTree 旁邊執行的小型服務（一個 Docker 容器），負責把「與你的公司有關」的事件，送到 App 右下角的 🔔 與右上角的小通知視窗，並保存每個人的已讀紀錄。

## 會通知什麼

| 事件 | 誰會收到 | 例子 |
|---|---|---|
| 📥 **調進**：別家公司或「無公司歸屬的帳號」（例如管理員）把庫存調進你的公司庫位 | 收件公司的人 | A 公司的 a-wh 把 80 件 A-P01-S1-XL 調進 B 公司 → B 公司的人收到 |
| 📤 **調出**：別家公司或無公司歸屬的帳號把庫存從你的公司庫位調走 | 被調出的公司的人 | 管理員把 A 公司的庫存調到 B → A 公司的人收到 |
| ⚠️ **大量**：單筆數量 ≥ 100（`large_qty`）的新增、移除、盤點、調貨 | 該庫存所在（及調貨雙方）公司的人 | A 公司的人移除 150 件 → A 公司其他同事收到 |
| ⚠️ **歸零**：移除或盤點後庫存變成 0 | 該庫存所在公司的人 | 盤點數量填 0 |
| 📉 **低庫存**：零件庫存低於「最小庫存」 | 該零件所屬公司的人 | A-P01-S1-XL 現有 40，最低標準 50 |

規則說明：
- **自己的操作不會通知自己。**
- **自己公司的人調動自家庫存**（同公司內調動，或調進自己公司）不通知同事，除非是大量或歸零。
- **無公司歸屬的帳號**（沒有加入任何 `company-X` 群組，例如管理員）所做的調動，一律會通知涉及的公司，並在通知上標示「無公司歸屬，可能是管理員」。
- **superuser** 預設看得到所有公司的通知（`superuser_sees_all`），但仍看不到自己的操作。
- 通知依使用者所屬的「公司群組」過濾，內容不會傳給不相關的公司。

## 已讀紀錄

- 存在伺服器，**換電腦、換瀏覽器登入同一個帳號，已讀狀態一致**。
- 事件通知：標示已讀後不再顯示為未讀。「全部已讀」只會標到你畫面上看到的最新一筆，之後才進來的事件仍是未讀。
- 低庫存通知：標示已讀後隱藏；**庫存變得更低**會再通知一次；補貨回到標準以上後，下次再低於標準會重新通知。
- 保存在 `inventree-data\notifier\state.json`，包含在 `backup.ps1` 的備份中。

## 運作方式（為什麼不需要額外帳號）

1. App 每 30 秒詢問一次 `/notify/api/feed`。
2. 通知服務把使用者**自己的登入憑證**轉給 InvenTree 的 `/api/user/me/` 確認身分與所屬群組。InvenTree 說他是誰就是誰；服務不儲存任何帳號、密碼或 token。
3. 服務用同一份憑證讀取 InvenTree 的**庫存異動紀錄**，依序處理新的紀錄並判斷事件。異動紀錄保存在 InvenTree，所以沒人開著 App 的期間不會漏掉，下一次有人開啟時會補上。

## 已知限制

- **不是推播**：App 開著時最多約 30 秒內出現通知；App 沒開就不會彈窗，下次開啟時會顯示未讀。
- **來源庫位靠自己記錄**：InvenTree 的「完整搬移」紀錄只有目的庫位，沒有來源。服務在第一次啟動時記下每筆庫存的位置，之後依異動紀錄更新。因此：
  - 第一次啟動之前發生的事不會通知（避免一開始就被歷史紀錄淹沒）。
  - 剛建立的庫存如果在服務處理它之前就被搬走，來源無從得知，只會通知「收件」那一方。
  - 如果有人用 InvenTree 以外的方式（例如直接改資料庫）移動庫存，服務不會知道。
- **資料庫還原到較舊的時間**時，服務會偵測到並重新開始（清掉舊事件與已讀進度）。
- **低庫存**依賴 InvenTree 的零件「最小庫存」設定（匯入腳本預設 10）。
- 事件只保留 60 天、最多 500 筆（`retention_days`、`max_events`）。

## 設定（`C:\Users\你的帳號\inventree\notifier\config.json`）

`setup-server.ps1` 會依 `inventree-seed\config.json` 的公司設定產生，重新執行時只更新公司清單，**保留你自行調整的其他欄位**。

| 欄位 | 預設 | 說明 |
|---|---|---|
| `companies` | 依匯入設定 | `name` 公司名稱（頂層庫位名稱）、`group` 公司群組、`code` 料號前綴（用來判斷低庫存屬於哪間公司） |
| `large_qty` | 100 | 視為大量的數量 |
| `superuser_sees_all` | true | superuser 是否看得到所有公司 |
| `retention_days` / `max_events` | 60 / 500 | 事件保留期限與筆數 |

修改後在安裝資料夾執行 `docker compose restart inventree-notifier`。

## 疑難排解

| 狀況 | 處理 |
|---|---|
| 🔔 是灰色的，提示「通知服務尚未啟用」 | 在安裝資料夾執行 `docker compose ps`，看 `inventree-notifier` 是否在執行；沒有的話重新執行 `setup-server.ps1` |
| 查看服務紀錄 | `docker compose logs --tail 50 inventree-notifier` |
| 通知清單頂端出現黃色警告 | 內容會說明原因，例如暫時讀不到 InvenTree，或目前帳號沒有庫存的檢視權限 |
| 一直沒有任何通知 | 確認：① 帳號有加入 `company-X` 群組 ② 你的操作不算（自己的操作不通知自己）③ 要用「另一個帳號」做測試 |
| 想清掉全部通知與已讀紀錄 | `docker compose stop inventree-notifier`，刪除 `inventree-data\notifier\state.json`，再 `docker compose start inventree-notifier`（會重新開始，不會產生歷史通知） |
