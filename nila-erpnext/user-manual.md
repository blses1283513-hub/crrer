# 妮菈穿戴甲系統 使用手冊（1.0.0）

給每天使用系統的同仁。系統架設與維護（安裝、備份、還原、更新）的完整說明在 [`production/README.md`](production/README.md)。

---

## 1. 開始使用

1. 用瀏覽器（Chrome 或 Edge）開 `http://主機IP:8090`（主機上可以用 `http://localhost:8090`）。主機 IP 請問管理員；建議把網址加入書籤。
2. 輸入**帳號**（例如 `may.a`，不是信箱）與密碼登入。第一次登入請到右上角頭像 →「My Settings」→「變更密碼」，換成自己的密碼。
3. 首頁點「**妮菈**」：只會看到你這個層級可以使用的功能。
4. 系統更新後畫面怪怪的：按一次 **Ctrl＋F5**。
5. 忘記密碼：請管理員在「帳號管理」幫你重設。

**名詞**

| 名詞 | 意思 |
|---|---|
| 款式／規格 | 一個款式（例：`0001` 櫻花）有多個規格，每個規格是「甲型 × 尺寸」 |
| 料號 | 規格的編號＝條碼內容＝SHOPLINE 的 SKU，例：`0001-LT-XS`（款式-甲型縮寫-尺寸） |
| 實際庫存 | 倉庫裡現在有的數量 |
| 預計庫存 | 實際庫存 − 未出貨訂單 ＋ 已下單還沒到的貨 |
| 在途 | 調撥中、已經離開調出倉、還沒到調入倉的貨 |
| 負庫存 | 先賣後入帳時會出現，代表帳上少了，要補入庫或盤點 |

## 2. 各層級每天要做的事

### 5 門市店員

| 什麼時候 | 做什麼 | 在哪裡 |
|---|---|---|
| 客人結帳 | 掃條碼（或輸入料號）→ 找會員（手機）或新增會員 → 結帳 | 妮菈 → 門市銷售 |
| 客人問有沒有貨 | 看自己門市的庫存 | 妮菈 → 庫存表 |

- 結帳時網路斷了：購物車會留著，網路恢復後再按一次「結帳」，**不會重複扣庫存**。
- 退貨、改價請找店長。

### 4 門市店長

店員的工作，再加上：

| 什麼時候 | 做什麼 | 在哪裡 |
|---|---|---|
| 客人退貨 | 輸入銷售單號或會員手機 → 選退貨（商品回庫存）或只退款 → 數量與金額 | 門市銷售 →「退貨／退款」 |
| 特價、折扣 | 結帳時在該行改單價 | 門市銷售 |
| 總公司調貨到店 | 打開調撥單 → 確認收到的貨 →「到貨入庫」 | 搜尋列輸入「物料移動」（調撥單的清單） |
| 盤點 | 新增盤點單，選自己的門市，輸入實際數量後送出 | 妮菈 → 盤點 |
| 看門市業績 | 依會員或明細，可匯出 Excel | 妮菈 → 消費報表 |
| 印標籤 | 選款式或輸入料號 → 列印 | 妮菈 → 條碼 |

### 3 總公司作業

| 什麼時候 | 做什麼 | 在哪裡 |
|---|---|---|
| 每天早上 | 看「銷售訂單」清單的**出貨狀態**：先處理「可出貨」 | 妮菈 → 銷售訂單 |
| 出貨 | 打開訂單 →「建立」→「銷售出庫」→ 確認數量後送出 | 銷售訂單 |
| 訂單缺貨但別家有 | 訂單上「調度」→「建立調撥單」；調入的一方收到後按「到貨入庫」 | 銷售訂單 |
| 門市要補貨 | 補貨建議 → 建議調撥 → 建立調撥單 | 妮菈 → 補貨建議 |
| 廠商送貨到 | 打開採購單 →「到貨入庫」→ 確認實收數量後送出 | 採購單 |
| 盤點 | 同店長，可選任何倉庫 | 妮菈 → 盤點 |

官網（SHOPLINE）的訂單會自動變成銷售訂單（客戶「官網散客」），和一般訂單一樣出貨。

### 2 營運主管

總公司作業的工作，再加上：

| 什麼時候 | 做什麼 | 在哪裡 |
|---|---|---|
| 每天（看到鈴鐺通知時） | 看補貨建議 → 勾選 →「建立補貨單（待叫貨）」；數量和建議不同要選原因 | 妮菈 → 補貨建議 |
| 向廠商叫貨後 | 補貨單 →「已叫貨（建立採購單）」 | 補貨單 |
| 新品上市 | 新增款式（勾甲型 × 尺寸、填成本與兩種售價、補貨目標） | 妮菈 → 新增款式 |
| 調價、停售、停產 | 打開**款式**修改，所有規格自動套用 | 商品 |
| 大量修改商品 | 匯出 → 修改 → 匯入（先預覽，全部正確才寫入） | 妮菈 → 商品匯入匯出 |
| 同一個人兩筆會員 | 打開要併掉的那一筆 →「合併到另一位會員」 | 妮菈 → 會員與客戶 |
| 辦抽獎 | 新增抽獎活動 → 條件 → 預覽 → 產生名單 → 匯出 Excel | 妮菈 → 抽獎活動 |
| 官網訂單有問題 | 處理「待處理」：修正 SKU 後「重新處理」，或人工處理後「標記已人工處理」 | 妮菈 → SHOPLINE 官網訂單 |

營運主管的工作，再加上：

|---|---|---|
| 新同事 | 新增帳號（姓名、帳號、層級、門市、初始密碼） | 妮菈 → 帳號管理 |

## 3. 常用操作的步驟

### 門市結帳

1. 妮菈 → 門市銷售（店長、店員只會看到自己的門市）。
2. 游標在料號欄，用掃碼槍掃條碼；同一個商品再掃一次數量 +1。找不到時會列出相近的規格讓你選。
3. 會員：輸入手機或姓名按「找」；沒有就按新增（姓名＋手機）。不選＝門市散客。
4. 確認金額 →「結帳」。

### 退貨／退款（店長以上）

1. 門市銷售 →「退貨／退款」→ 輸入銷售單號或會員手機。
2. 選那一筆銷售，輸入要退的件數；退款金額可以改小（部分退款）。
3. 「退貨」：商品回到門市庫存。「只退款」：商品不回來（例如瑕疵讓客人留著）。

### 庫存表

- 每款一個區塊，橫列是各公司、全公司合計、建議補貨；直欄是甲型 × 尺寸。
- 顏色：深紅＝負庫存、淺紅＝缺貨、黃＝低於補貨目標（只看全公司合計）。
- 點任何數字可以看異動明細。「顯示」可切換實際庫存／預計庫存。

### 盤點

1. 妮菈 → 盤點 → 新增。
2. 選倉庫，加入要盤的規格（可以只盤一部分），在「數量」輸入實際點到的數量。
3. 儲存後「送出」。系統自動算出差異並調整庫存。

### 抽獎（營運主管以上）

1. 妮菈 → 抽獎活動 → 新增：名稱、消費期間、門市（不選＝全部）。
2. 資格條件（可多條，全部都要符合）：累計金額、消費次數、單筆最高、買過指定款式或甲型。
3. 名額：每人 1 個、每滿 X 元 1 個、每 N 次消費 1 個（可設上限）。
4. 「預覽」看人數 →「產生名單」存成快照 → 匯出 Excel。只算門市消費（扣掉退貨），官網訂單不算。

## 4. 管理員維護篇

以下指令在主機上的 PowerShell 執行，先切到安裝資料夾：

```powershell
cd C:\Users\你的帳號\nila-erpnext\production
```

| 要做的事 | 指令 | 多久一次 |
|---|---|---|
| 檢查系統 | `powershell -ExecutionPolicy Bypass -File .\check-nila.ps1` | 每週，或覺得怪怪的時候 |
| 打不開、出現 502 | `powershell -ExecutionPolicy Bypass -File .\check-nila.ps1 -Fix` | 需要時 |
| 立刻備份 | `powershell -ExecutionPolicy Bypass -File .\backup-nila.ps1 -CopyTo "G:\我的雲端硬碟\妮菈備份"` | 大量修改前 |
| 還原演練 | `powershell -ExecutionPolicy Bypass -File .\drill-nila.ps1` | 每月 |
| Administrator 忘記密碼 | `powershell -ExecutionPolicy Bypass -File .\reset-admin-password.ps1` | 需要時 |
| 還原（會取代全部資料） | `powershell -ExecutionPolicy Bypass -File .\restore-nila.ps1 -BackupDir "備份資料夾"` | 真的出事時 |
| 更新到新版本 | 在新下載的資料夾執行 `update-nila.ps1` | 有新版時 |

**健康檢查看到 ✗ 時**

| 訊息 | 怎麼辦 |
|---|---|
| Docker 沒有執行 | 開啟 Docker Desktop，等鯨魚圖示不再轉動，再執行一次 |
| 網頁沒有回應 | 執行 `check-nila.ps1 -Fix` |
| 已經 xx 小時沒有備份 | 確認主機在 23:30 有開著；手動執行一次備份 |
| 第二個地方找不到這份備份 | 確認雲端硬碟電腦版有登入、雲端資料夾還在 |
| 磁碟只剩 xx GB | 清理電腦上的檔案（備份資料夾只會保留最近 30 份） |
| 上次還原演練失敗 | 換一份較新的備份再演練；仍失敗請聯絡維護人員 |

**停電之後**：電腦會自己開機並啟動系統（需完成 README「上線設定」）。約 5 分鐘後打開網頁確認；打不開就執行 `check-nila.ps1 -Fix`。

**官網訂單（SHOPLINE）**：設定與規則見 README「SHOPLINE 官網訂單」。API 金鑰只貼在系統的設定欄，不要貼到聊天、信件或文件。

## 5. 常見問題

| 問題 | 答案 |
|---|---|
| 庫存變成負數 | 代表先賣了、帳上還沒入庫。確認是否有調撥或進貨還沒按「到貨入庫」；都沒有就盤點 |
| 停售的商品能不能賣 | 門市可以賣（出清），但不能建立新的銷售訂單；停產的不會再出現在補貨建議 |
| 官網的訂單算不算會員消費 | 不算。會員消費與抽獎只算門市 |
| 補貨建議的數字怎麼來的 | 補貨目標 − 全公司預計庫存（總公司＋分公司＋在途 − 未出貨訂單 ＋ 已叫貨） |
| 為什麼看不到成本 | 成本與進價只有 1 管理員、2 營運主管看得到 |
| 看不到某個功能 | 每個層級只看到自己可以用的功能；需要的話請管理員調整層級 |
