# 妮菈穿戴甲：ERPNext 16 正式版

官方 ERPNext 16 ＋ 妮菈客製功能（`nila_app`），裝在客戶的電腦上，客戶是最高權限的使用者（`Administrator`）。
只供**同一個區網**使用（`http://電腦IP:8090`），不對外開放；之後若要讓門市或手機從外面連進來，再加對外通道即可，不需要重裝。

> 開發進度：**P0–P7 已完成**——安裝、更新、備份、還原；商品；庫存表、全公司補貨、訂單調度；門市銷售與會員；帳號、權限與抽獎；SHOPLINE 官網訂單同步（預設關閉）。
> 最後的 P8（搬到客戶電腦、自動啟動、每日備份演練、正式資料匯入與驗收）完成後就是 1.0.0。更新都用 `update-nila.ps1`，資料不受影響。

## 需要什麼

- Windows 10／11，已安裝並啟動 **Docker Desktop**。
- C 槽至少 **15 GB** 可用空間（ERPNext 映像約 7 GB）、Docker 可用記憶體 4 GB 以上。
- 可以上網（第一次安裝要下載約 1.4 GB）。
- 不需要系統管理員權限；只有「開放區網其他電腦連入」與「每天自動備份」的登記可能需要。

## 安裝（第一次）

1. 下載並解壓縮專案，開一般的 PowerShell，切到 `nila-erpnext\production`：

   ```powershell
   cd "解壓縮的位置\nila-erpnext\production"
   powershell -ExecutionPolicy Bypass -File .\install-nila.ps1
   ```

2. 第一次執行會在 `C:\Users\你的帳號\nila-erpnext\production\nila-config.json` 放一份設定範本後停下。用記事本打開確認：

   | 欄位 | 說明 |
   |---|---|
   | `company_name`、`company_abbr` | 公司名稱與縮寫（縮寫 2–5 個大寫英文字母，會出現在倉庫名稱後面） |
   | `hq`、`branches` | 總公司與各分公司（門市）名稱。之後可再新增分公司 |
   | `shapes` | 甲型名稱與縮寫（2–3 個大寫英文字母）。**縮寫是料號的一部分（例：`0001-LT-XS`），開始使用後不能改**；之後可再新增甲型 |
   | `sizes` | 尺寸，預設 XS、S、M、L |

3. 存檔後**再執行一次同樣的指令**。設定最高管理員密碼（至少 10 個字元，輸入兩次），確認變更後輸入 `Y`。
4. 第一次約 10–30 分鐘。完成後瀏覽器會開啟 <http://localhost:8090>，用 `Administrator` 與剛才的密碼登入。

- 埠 8090 被占用時：加上 `-Port 8091`。
- 中途失敗：直接再執行一次（沿用密碼，資料不會重複建立）。
- 安裝完成後，`.env` 只留資料庫密碼；管理員密碼已從檔案中移除。**`.env` 請勿分享。**

## 讓同一個區網的其他電腦使用

以**系統管理員身分**開 PowerShell，開放 8090 埠（只限私人與網域網路）：

```powershell
New-NetFirewallRule -DisplayName "妮菈 ERPNext (TCP 8090)" -Direction Inbound -Protocol TCP -LocalPort 8090 -Action Allow -Profile Private,Domain
```

其他電腦用瀏覽器開 `http://主機IP:8090`（主機 IP 用 `ipconfig` 查）。主機的網路要設為「私人網路」，IP 建議在路由器固定。

## 備份（非常重要：主機沒有 UPS）

```powershell
cd C:\Users\你的帳號\nila-erpnext\production
powershell -ExecutionPolicy Bypass -File .\backup-nila.ps1 -CopyTo "D:\妮菈備份"
```

- 每份備份放在 `文件\妮菈備份\日期時間\`（資料庫、上傳檔案、網站設定），保留最近 30 份。
- `-CopyTo` 指定**第二個地方**（隨身碟、NAS、或 Google Drive／OneDrive 的同步資料夾）。電腦壞掉時，只有放在別處的備份救得回來。
- **每天自動備份**（每天 23:30，電腦與 Docker 要開著）：

  ```powershell
  powershell -ExecutionPolicy Bypass -File .\backup-nila.ps1 -CopyTo "D:\妮菈備份" -RegisterDaily
  ```

## 還原

⚠️ 會用備份的內容**取代目前的全部資料**。還原前會自動先備份目前的資料。

```powershell
powershell -ExecutionPolicy Bypass -File .\restore-nila.ps1 -BackupDir "C:\Users\你的帳號\Documents\妮菈備份\20261013_233000"
```

輸入 `YES` 確認。完成後請用**備份當時**的帳號密碼登入（帳號密碼存在資料庫中，會一起還原）。

**換電腦**：在新電腦依「安裝」完成安裝（`nila-config.json` 用舊電腦備份資料夾中的那份），再用上面的指令還原舊電腦的備份。

## 更新到新版本

下載新版並解壓縮後，在**新下載的** `nila-erpnext\production` 資料夾執行：

```powershell
powershell -ExecutionPolicy Bypass -File .\update-nila.ps1
```

會先自動備份，再替換程式、重新建置、升級資料庫結構並重新啟動（約 3–10 分鐘）。`.env` 與 `nila-config.json` 不會被改動。完成後各電腦按一次 Ctrl+F5。

## 商品

一個**款式**（例：`0001` 櫻花）有多個**規格**，每個規格是一種「甲型 × 尺寸」，料號為「款式編號-甲型縮寫-尺寸」（例：`0001-LT-XS`）。料號也是條碼內容與 SHOPLINE 的 SKU。

| 要做的事 | 怎麼做 |
|---|---|
| 新增款式 | 「商品」清單 →「新增款式」：輸入名稱、成本、官網售價、實體售價，勾選要有的甲型 × 尺寸，填各甲型的補貨目標 →「建立」。款式編號留空會自動編號（0001、0002…），**建立後不能改**；款式名稱可以重複 |
| 既有款式加新的甲型／尺寸 | 打開款式 →「加入甲型／尺寸」，勾選新的組合（已有的會顯示為已勾選） |
| 改成本、售價、商品狀態、款式名稱 | 打開**款式**修改後儲存，所有規格自動套用（含兩個價格表的售價）。規格上這些欄位不能改，售價也不能在規格上單獨改 |
| 改某個規格的補貨目標 | 打開該規格修改「補貨目標」（建立時同甲型的各尺寸預設相同） |
| 大量建立或修改 | 「商品」清單 →「匯入／匯出」（見下） |

**商品狀態**

| 狀態 | 銷售訂單（官網、訂單調度） | 門市銷售 | 補貨建議 |
|---|---|---|---|
| 上架 | ✅ | ✅ | ✅ |
| 停售 | ❌ 不能建立 | ✅（出清庫存） | ✅ |
| 停產 | ❌ 不能建立 | ✅（出清庫存） | ❌ 不再補貨 |

**匯入／匯出（試算表）**

1. 「下載空白範本」或「匯出全部商品」（匯出含各公司目前庫存，可直接修改後再匯入）。
2. 一列＝一個規格。欄位：SKU 編碼（可留空）、款式編號、款式名稱、甲型、尺寸、商品狀態、成本、官網售價、實體售價、補貨目標、各公司庫存。
   - 款式編號留空＝新款式，同名稱的列會成為同一個款式，匯入時自動編號。
   - 同一款式各列的名稱、狀態、成本、售價要一樣。已存在的款式，這些欄位留空表示不變。
   - 各公司欄位是**新規格的期初庫存**；已經存在的規格不會改庫存（預覽時會提醒），庫存調整請用盤點。
3. 上傳後會先**預覽**：列出新增、更新的數量，以及每一列的錯誤（含列號），這時還沒有寫入任何資料。
4. 沒有錯誤才能按「開始匯入」。匯入在背景執行（可關閉頁面，回來會看到進度與結果），**全部成功才寫入，任何一筆失敗就全部不寫入**。
   第一次匯入全部商品（約 5,000 個規格＋5 個公司的期初庫存）約需 30 分鐘，請在沒有人操作庫存時進行（匯入完成前，其他人的盤點單會等它結束才能過帳）。

> 安裝精靈建立的英文預設倉庫（Stores、Finished Goods、Work In Progress、Goods In Transit）會自動停用，預設倉庫改為「總公司」。

## 庫存表

「商品」清單 →「庫存表」（或在搜尋列輸入「庫存表」）。

- 每款一個區塊：列＝總公司、各分公司（有在途的貨時多一列「在途」）、**全公司合計**、**建議補貨**；欄＝甲型 × 尺寸＋小計。沒有的規格留白。
- 顏色：深紅＝負庫存、淺紅＝缺貨（0）、黃＝低庫存（全公司合計低於補貨目標）。缺貨、低庫存只看「全公司合計」列；各公司只標負庫存（分公司多半是 0，全標出來反而看不到真正的問題）。
- 上方篩選：款式編號或名稱、甲型、尺寸、公司、商品狀態、庫存狀態、只看需補貨；「顯示」可切換**實際庫存**與**預計庫存**（已扣訂單、已加補貨單與已叫貨）。
- 點任一個數字：看該格的異動明細（預計庫存模式則看預計庫存報表）。「匯出 Excel」匯出全部符合條件的款式。
- 庫存可以是負數（例如先出貨、門市先賣，之後再入庫），系統已開啟「允許負庫存」。

## 補貨（全公司合計）

「庫存表」→「補貨建議」。

- **建議補貨數＝補貨目標 − 全公司預計庫存**（總公司＋各分公司＋在途，已扣訂單、已加補貨單與已叫貨）。例：總公司 2＋分公司 1 − 訂單 5＝−2，目標 10 → 補 12。停產不補；補貨目標 0 的不補。
- **建議調撥**：某個出貨倉的庫存不夠出訂單、其他公司有剩時，先建議調撥（例如門市調回總公司），不夠的部分才算進叫貨。
- 勾選後按「建立補貨單（待叫貨）」或「建立調撥單」。數量改得和建議不同時**要選原因**，會留下「調整紀錄」。負庫存可以按「標註」記錄原因。原因的選項在「原因選項」自行新增或停用。
- 建立補貨單後，補貨單的數量會算進預計庫存，**建議數自動變 0，不會重複叫貨**。

| 補貨單狀態 | 意思 | 下一步 |
|---|---|---|
| 待叫貨 | 補貨單已建立 | 向廠商叫貨後，在補貨單按「已叫貨（建立採購單）」（廠商預設「預設廠商」，單價＝成本） |
| 已叫貨 | 已建立採購單，等廠商送貨 | 貨到時在採購單按「到貨入庫」，確認實收數量後送出 |
| 已到貨 | 已入庫到總公司 | — |

每天早上系統會自動重算，有需要補貨或調撥時，在右上角通知（鈴鐺）提醒庫存管理者。

## 訂單調度

- **出貨倉**：預設總公司，可改成任何一家分公司（訂單的「發料倉」或每一行的倉庫）；不能選在途倉。
- 訂單畫面在明細上方顯示「**各倉庫存與調度**」：每一行在各公司的庫存，以及分配結果（現貨、在途、調撥、已叫貨、還缺）。還沒送出的訂單排在所有已送出訂單之後計算（先來先用）。
- 訂單的**出貨狀態**（訂單清單可篩選）：

| 出貨狀態 | 意思 |
|---|---|
| 可出貨 | 出貨倉的現貨足夠 |
| 待調撥 | 要從其他公司調貨，或調撥的貨在途中 |
| 已叫貨 | 差的數量要等已叫貨（採購單）到貨 |
| 待叫貨 | 全公司都不夠，需要叫貨（會出現在補貨建議） |
| 已出貨 | 全部出貨完成 |

- 缺貨時，在送出的訂單按「調度」→「**建立調撥單**」：調出倉的貨立即轉到在途；調入倉收到後，在調撥單按「**到貨入庫**」。
- 入庫、調撥、出貨、門市銷售、盤點、採購單、訂單修改或取消後，相關訂單的出貨狀態自動重算；每天早上再全部重算一次。
- 出貨：在訂單按「建立」→「銷售出庫」。取消訂單會釋放預留；若有還在途的調撥單會提醒你（貨到後留在調入倉，可用在其他訂單，不需要就取消調撥單）。

## 門市銷售與會員

**門市銷售**（搜尋列輸入「門市銷售」）：在門市的電腦或平板（同一個區網）使用，可接掃碼槍。

1. 選門市（門市帳號固定是自己的門市）。
2. 掃碼或輸入料號後按 Enter；同一個商品再掃一次數量 +1。找不到完全相同的料號時，會列出名稱或料號相近的規格讓你選。
3. 會員：輸入手機或姓名按「找」；找不到可以直接新增（只要姓名與手機）。不選會員＝門市散客。
4. 按「結帳」：建立已收款（現金）的銷售，扣該門市庫存。庫存不夠也能賣（負庫存）；停售、停產的商品門市仍可賣。
   - 價格預設「實體售價」；店長（含）以上可以在單筆改價或打折，店員不行。
   - 網路斷掉時購物車會保留，再按一次「結帳」即可；系統用結帳代碼辨認，**不會重複扣庫存**。
5. **退貨／退款**（店長以上）：輸入銷售單號或會員手機 → 選要退的件數與金額。
   - 退貨：商品退回該門市庫存，可以只退部分金額。
   - 只退款：商品不退回（例如瑕疵讓客人留著），視同處理 1 件。
   - 部分退款只扣退款金額（Q9）。

**會員**：手機號碼自動統一成 09xxxxxxxx（`+886 912-345-678` 也可以），不能重複。同一個人有兩筆會員資料時，營運主管以上可以合併（消費紀錄移到保留的那一筆）。

**消費報表**（店長以上；店長只看自己的門市）：依會員、依門市或明細，顯示消費次數、銷售金額、退款金額與淨額，可匯出 Excel。**只計門市銷售，官網訂單不算**（Q7）；抽獎（P6）用同一個計算。

**條碼**（「商品」清單 →「條碼」）：選款式或輸入料號，產生每個規格的條碼（內容＝料號，Code 128），可直接列印或另存圖檔。

| 層級 | 門市銷售 | 退貨／退款 | 改價 | 合併會員 | 消費報表 | 條碼 |
|---|---|---|---|---|---|---|
| 管理員、營運主管 | ✅ 全部門市 | ✅ | ✅ | ✅ | ✅ 全部門市 | ✅ |
| 總公司作業 | ✅ 全部門市 | ❌ | ❌ | ❌ | ❌ | ✅ |
| 門市店長 | ✅ 自己的門市 | ✅ | ✅ | ❌ | ✅ 自己的門市 | ✅ |
| 門市店員 | ✅ 自己的門市 | ❌ | ❌ | ❌ | ❌ | ❌ |

> 每筆銷售會記錄「收銀人員」（實際操作的帳號）。

## 帳號與權限

**帳號管理**（只有管理員；首頁「妮菈」→「帳號管理」）：

- **新增帳號**：姓名、帳號（登入用，英文小寫或數字，例如 `may.a`）、層級、門市（店長、店員必選）、初始密碼。不需要信箱，登入時直接輸入帳號。
- 可以修改層級與門市、停用（資料保留、不能登入）、重設密碼。不能停用或降級自己，也不能修改內建的 Administrator。
- 密碼要夠強（ERPNext 的密碼強度檢查），太簡單會被拒絕。
- **建議**：最高管理員替自己也建一個「1 管理員」的帳號平常使用，內建的 Administrator 留作備援；這樣每筆單據會顯示真正操作的人。

| 盤點 | ✅ | ✅ | ✅ | ✅ 自己的門市 | ❌ |

- 每個人登入後點首頁的「妮菈」，只會看到自己有權限的功能。

## 抽獎

首頁「妮菈」→「抽獎活動」→ 新增：

1. 活動名稱、消費期間、適用門市（不選＝全部門市）。
2. **資格條件**（可以加多條，全部都要符合）：累計消費金額、消費次數、單筆最高金額、買過指定款式、買過指定甲型（款式、甲型可填多個，用逗號分隔，買過其中一個即可）。
3. **名額**：每人 1 個、每滿 X 元 1 個、每 N 次消費 1 個（後兩種可設每人上限）。
4. 按「預覽」看符合的人數與名單；按「產生名單」存成**名單快照**（記錄當時的條件，日後退貨或改條件都不會變），可以匯出 Excel。條件可以隨時修改再重新產生，舊的名單都保留。

- 消費＝門市銷售扣掉退貨、退款（和消費報表同一個計算）；**整筆退掉的銷售不算一次消費**；官網訂單不算；只算會員。
- 系統只判斷資格並匯出名單，不負責抽籤（Q10）。

## SHOPLINE 官網訂單

官網（SHOPLINE）的訂單會自動匯入成「銷售訂單」，由「訂單調度」安排出貨。**預設關閉**，設定好才會開始。

**第一次設定**（只有管理員；首頁「妮菈」→「SHOPLINE 官網訂單」）：

1. 先在 SHOPLINE 取得 API 金鑰：後台「設定 → 管理員設定 → API 權限（API Auth）」。這個功能要先向 SHOPLINE 窗口申請開通；建立時可以設定到期日與 IP 白名單（若有設定，要加入這台電腦對外的 IP）。
2. 把金鑰貼到「API 金鑰」欄，按「**測試連線**」：成功會顯示商店名稱，並自動帶入商店代號。
3. 「從這個時間之後的官網訂單開始匯入」：空白＝從啟用的那一刻開始（以前的訂單不匯入）。若要補匯入，填想要的開始時間。
4. 勾「啟用自動同步」→「儲存設定」。之後每 5 分鐘（可改，最少 2 分鐘）自動查一次；也可以按「立即同步」。

> **金鑰等同商店的密碼**：只貼在這個設定欄，不要貼到聊天、信件或文件，也不需要給開發人員。系統把金鑰加密保存，畫面只顯示最後 4 碼；營運主管看得到同步狀態，看不到金鑰。金鑰到期或被停用時，同步會失敗並通知管理員，換上新的金鑰即可，期間的訂單會在下次成功時補上。

**匯入規則**：

- 每筆官網訂單 → 一張已送出的銷售訂單：客戶「官網散客」、銷售管道「官網」、從總公司出貨（之後可在訂單上改出貨倉）、單價用扣掉折扣後的金額；訂單上記著官網訂單編號。總公司缺貨也照樣建立，出貨狀態會顯示「待調撥／待叫貨」。
- **SHOPLINE 商品的 SKU 必須等於系統的料號**（例如 `0001-LT-XS`，大小寫不拘）。對不到的訂單不會建立，放進「**待處理**」。
- 同一筆官網訂單只會建立一次（重複查到不會重複建立）。
- 官網**取消、刪除或全額退款**：還沒出貨的銷售訂單自動取消；已經出貨的放進「待處理」，請人工辦理退貨。
- 建立之後官網又修改了商品或數量：不會自動改訂單，放進「待處理」請人工確認。
- 官網的退貨、換貨單放進「待處理」；SHOPLINE 門市 POS 的訂單預設不匯入（門市銷售在妮菈系統做）；暫存中的訂單等確認後才建立。
- 官網訂單**不計入會員消費與抽獎**（Q7）；停售的商品若官網仍賣出，訂單照樣建立，請記得在官網下架。

**處理待處理**：在清單選「待處理」，看「說明」欄的原因：

- 料號對不到 → 在 SHOPLINE 把 SKU 改成系統的料號（或在系統新增該商品），再按「**重新處理**」。
- 已經人工處理好（例如手動建立了訂單、已退貨）→ 按「**標記已人工處理**」並寫下怎麼處理的。之後官網若又有變動，系統會重新判斷。

有新的待處理或同步失敗時，管理員與營運主管會收到系統通知（右上角鈴鐺）。
